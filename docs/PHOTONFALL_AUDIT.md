# PhotonFall 技术审查

这份文档逐项核对项目现有知识点的科学准确性、简化程度和资料来源，是升级工作的基础。按 spec 的要求：**先审查、再写 SPEC、最后动代码**。

本文只记录结论和改法，不含实现。每项修复在独立 PR 完成。

## 可信度标签

每个知识点标注下面之一：

- **Confirmed** — 有官方/论文/标准可查。
- **General Principle** — 通用科学原理（物理、信息论、色彩学教材里的标准内容）。
- **Simplified Model** — 为教学简化的模型（例如把变焦镜头抽象成等效主平面）。
- **Conceptual Illustration** — 示意图，参数或布局不代表真实器件。
- **Vendor Specific** — 某厂商的具体实现，不能推广。
- **Estimated** — 公开资料不足，按业界常见做法估算。
- **Needs Verification** — 暂未复核，待核对。

动代码时，对应标签以 HTML 注释或抽屉里的小字（class `cal`，待加）展示。

## P0 发现

### P0-1 · FSI / BSI / 堆栈式 的分类维度（[js/steps.js:85](js/steps.js#L85), 第 18 步「三种像素结构」）

**现状**

- 标题：「三种像素结构：前照式、背照式、堆栈式」。
- Lead 把三者并列成一条「代」的进化链。
- adv 里已经写到「堆栈式和背照式一模一样，因为它改的不是像素内部」，即内部承认堆栈式建在背照式之上。
- hard 表并列三列，像三种互斥结构。

**问题**

把两个正交维度压成了一个线性进化：

| 维度 | 含义 | 可选值 |
|---|---|---|
| 受光面 | 光从哪一面进硅 | FSI（正面）/ BSI（背面） |
| 晶圆集成 | 像素阵列和外围电路/其他电路是否在同一片硅上 | Monolithic（单层）/ Stacked（多层键合） |

真实组合：

- **FSI + Monolithic** — 早期 CMOS（2000 年代主流）。
- **BSI + Monolithic** — 2008 Sony Exmor R 之后到 2012 左右的主力。
- **BSI + Stacked** — 2012 Sony Exmor RS 开始至今的手机/相机旗舰。
- **FSI + Stacked** — 极少，但原理上存在（有的车载/工业传感器因为堆叠工艺选择是 FSI）。

把"堆栈式"当成「BSI 之后的下一代」会误导读者以为堆栈必然意味着 BSI，或者以为"堆栈"指像素结构的变化。

**改法**

- 标题改成「像素结构两个维度：受光面 + 晶圆集成」。或者保留现标题但加副标题「两个维度的常见组合」。
- Lead 重写：点明两个维度，再说"现在手机旗舰几乎都是 BSI + Stacked"。
- 加一个 2×2 表显示四种组合和代表产品 / 年代。
- hard 表拆成两张：一张 FSI vs BSI（只讲受光面），一张 Monolithic vs Stacked（只讲集成方式）。
- adv 里原来说"堆栈式和背照式一模一样"的那句话可以保留并强化：这正是两个维度正交的直接结论。
- 3D 场景的四根柱子也要调整示意：现在前三根暗示"代际"，可以改成"BSI + Mono"与"BSI + Stacked"的对比，另加一根"FSI + Mono"作为历史参考。

**标签**：Simplified Model（教学二维简化成一维）→ 应为 General Principle。

**参考**

- Sony "Back-Illuminated CMOS Image Sensor" 技术页。
- Sony 2012 Exmor RS 新闻稿（首款 stacked CIS 量产）。
- TechInsights 拆解报告（BSI vs Stacked 架构对比）。
- IEEE J-SSC 相关论文（Hybrid Bonding、Wafer-to-Wafer）。

### P0-2 · LOFIC 内容（[js/steps.js:63](js/steps.js#L63), 第 17 步）

**现状**

- 原理讲解（adv 前半）正确：PD → 溢出到大电容 → 两次读出（HG/LG）→ 片内合成。
- DCG vs LOFIC 对比表（hard 前）正确。
- 新加的「各家 LOFIC 方案」一节讲了 Sony / 豪威 / 思特威 / 三星。

**问题**

- 没标 Vendor Specific。四家的「电容形态与位置」列全部是公开资料的推断，不是确证。
- 2026-11-16 以后发布的几款产品（Sony LYT-910、IMX908）日期和参数来自搜索结果，属于 Confirmed 但**本文档最后一次复核日期**没记录。
- 「单次曝光内三帧融合」对思特威 LOFIC HDR 3.0 的描述来自厂方营销材料，严格说是 Vendor Specific + 口径不明。

**改法**

- 在 adv 下方「各家 LOFIC 方案」加一行小字：「以下为 Vendor Specific 内容，电容形态为公开资料推断」。
- hard 「电容形态」列全部加 `(推断)` 或改用 Needs Verification 标签。
- 来源那一段注明："最后核对：2026-11-16"。
- 考虑把思特威「三帧融合」改成「分段读出，最多三档增益"（已知公开信息的最保守描述）。

**标签**：Vendor Specific + Estimated。

## 方法论

1. 每个发现指明现状代码位置、问题、改法、参考资料。
2. 改法先落到相应 SPEC 文档（待建）或本文档的 appendix，再写代码。
3. 一次 PR 对应一个 P0/P1 条目，不打包。
4. 现有功能不破坏为底线，渐进替换。
5. 每次 PR 跑 `node tests/check.js`，视觉改动起本地 server 真打开。
