# PhotonFall 重做：小白由浅入深 + 技术演进线

日期：2026-11-13　状态：待用户确认（章节划分、步骤编号、结构 B、浅色科普书风格、实现方式已在对话中确认）

## 为什么做

PhotonFall 现在是一页 31 步的相机成像 3D 讲解，内容扎实，但对新手不友好：

- 导航只有 1–31 的数字，看不出章节，也不知道自己走到了哪里。
- 讲解文字密，长段落加表格；控件和小图排在文字后面，要往下滚才找得到。
- 文字和 3D 场景没有联动。
- 第 25–31 步的视觉和前 24 步各是一套。
- 只讲"现在怎么工作"，不讲"为什么会变成这样"。

目标读者是**完全不懂相机的人**。他们要能从零开始，由浅入深，一路看懂相机怎么把光变成照片；同时能顺着年代，看懂技术怎么一代代迭代：新技术解决了旧技术的什么问题、带来了什么新问题、是什么新需求推动的、又怎么重塑了整个行业。

## 目标

1. **原理线**：保留并整理现有 31 步，新增第 0 章"先看全景"。每一步分三层：
   - 入门：一两句大白话加一个比喻，默认展开。
   - 进阶：现有讲解文字，默认折叠。
   - 硬核：公式、表格、厂商细节，默认折叠。
2. **演进线**：新增 20–25 个技术演进节点，分五条泳道，有一个总时间轴视图。每个节点固定回答四个问题：解决了什么 / 新问题 / 推动力 / 行业变化。
3. **两条线互通**：讲解页挂演进卡，点了跳到时间轴；时间轴卡片有"去看原理"，点了跳回对应步骤。
4. **交互更顺**：按章节导航，有进度提示；控件紧跟入门层；入门文字里的关键词可以点，点了在 3D 里高亮对应部件。
5. **视觉统一**：浅色科普书风格的讲解栏，加深色 3D 舞台。

## 非目标

- 不引入框架（React / Vue 等），不加构建步骤，不升级 three.js（保持 r128）。
- 不给时间轴另做 3D 场景，时间轴只用 2D 配图或小动画。
- 不改现有 3D 场景的物理和动画逻辑，只加高亮钩子、调标注样式。
- 不做多语言、账号、后端。

## 反目标（技术上能跑，但算失败）

- 改完之后信息反而更密、更难读。
- 入门层只是把术语缩短，小白读完还是不懂。比喻必须是日常事物。
- 双击 `index.html` 就能打开的能力丢了。
- 现有交互退化，例如变焦、对焦、光圈、快门、ISO、拍照，以及各步的按钮和滑块。
- 历史事实写错，或者把示意值当成事实来写。

## 约束

- 所有脚本都是普通 `<script>`，靠加载顺序共享顶层变量，不能用 ES modules：`file://` 下会被浏览器拦截。
- 不能用 `fetch` 读本地数据，同样是因为 `file://`。数据写成 JS 文件里的常量。
- three.js r128 和 OrbitControls 从 CDN 加载，需要联网。
- 场景注册方式：`app.js` 里的 `GR` 对象，加上 `frame()` 里的 `else if(X.visible)animX()` 分派；默认分支是 micro 场景的动画。
- 可选面板用 `data-pn` 属性，由每一步的 `pn:[...]` 控制显示。
- 讲解栏的小图都是 canvas，颜色写死在各个画图函数里，目前按深色背景调。

## 考虑过的做法

| 做法 | 取舍 | 结论 |
|---|---|---|
| **在现有页面上改造**：保留单页和全部 3D，扩展 `steps.js` 字段，新增演进数据文件，重写讲解栏和 CSS；时间轴是同页里的另一个视图，用网址里的 `#` 区分 | 改动集中在讲解栏和数据，3D 基本不动；跳转瞬间完成；每步都有能分享的链接 | **选这个** |
| 把内容抽成 JSON / Markdown 再加载 | 内容和代码最干净，但 `file://` 下读不了，必须起服务器 | 不选 |
| 拆成多页，每章一个 HTML | 链接直观，但每次翻页 3D 都要重建，共享状态也要重理 | 不选 |

页面结构也比较过三种：两个独立模式、原理为主嵌演进卡、按年代讲故事。用户选了**原理为主，演进嵌在每一步里**。视觉风格比较过深色科技、浅色科普书、相机工业风，用户选了**浅色科普书**。

## 已定的设计

### 章节

| 章 | 名称 | 步骤 |
|---|---|---|
| 0 | 先看全景 | 新写 1 步：光 → 镜头 → 传感器 → 电路 → 照片，30 秒走完全程 |
| 1 | 镜头 | 现第 1–8 步 |
| 2 | 进传感器前 | 现第 9–12 步 |
| 3 | 像素 | 现第 13–15 步 |
| 4 | 结构 | 现第 16–19 步 |
| 5 | 读出与处理 | 现第 20–24 步 |
| 6 | 周边 | 现第 25–31 步 |

步骤编号改成从 0 开始，全景是第 0 步，原来的第 N 步编号不变。

第 0 步的 3D：复用 `macro` 场景，用镜头动画把整条链路走一遍（景物 → 镜头 → 传感器）。镜头最后推到传感器表面，再用文字和一个简单示意交代"之后电路和 ISP 把它变成照片"。*（实现者的决定）* 每次进入第 0 步都自动播放一遍，配一个"重播"按钮；用户一拖动画面就停止导览。第 0 步不显示变焦、对焦、光圈等相机控件和取景器，需要给步骤加一个开关来覆盖"`macro` 场景就显示相机控件"的现有规则。

**内容由谁写**：全部在这次的范围里。入门文字、比喻、进阶和硬核两层的拆分、演进节点，都由实现者撰写；历史事实逐条上网核对，优先用厂商官网、技术论文、主流媒体报道。演进数据写完后先停一下，把节点列表（标题、年份、四格摘要）交给用户过目，确认后再接到界面上。

### 讲解页布局（电脑）

左边讲解栏，右边 3D 舞台。讲解栏从上到下：

1. 章节导航（0–6 章，外加"🕰 时间轴"入口），下面一条全局进度条，再下面一行本章各步的标题，可点。
2. 步骤标题。
3. **入门层**：大字号，带比喻；关键词可点。
4. **本步控件**：滑块、按钮，以及取景器、透光曲线等小图。原来的 `ctl`、`vfwrap`、`data-pn` 面板都移到这里。
5. **进阶**（折叠）：原有讲解文字。
6. **硬核**（折叠）：公式、对比表、厂商细节。不是每一步都有。
7. **演进卡**：0–N 张，每张显示标题、年份和四格摘要，点了跳到时间轴对应节点。
8. **本步元器件**（折叠）：保留现在 `#compwrap` 的元器件列表和 `listComps()` 的功能；点 3D 标注弹出说明的交互也保留。*（实现者的决定）*
9. 上一步 / 下一步，显示相邻步骤的标题。

键盘左右方向键切换步骤的功能保留。

### 关键词高亮

入门文字里用标记写关键词，例如 `<k data-hl="pd">小水桶</k>`。每个场景为自己的部件注册高亮目标（id → 网格或标注）。点击或悬停关键词时，3D 里对应的目标高亮（发光或描边，加上标注强调），一两秒后恢复；点击同时把镜头轻微转向目标。每一步至少有一个可高亮的关键词；第 25–31 步的新场景也要配上。

**3D 代码能改到什么程度** *（实现者的决定）*：运动和动画逻辑不动；材质、颜色、标注样式可以改。高亮如果需要，可以给目标网格单独克隆一份材质，因为很多网格共用 `basic()` 和 `std()` 生成的材质。

### 时间轴视图（`#/timeline`）

- 整宽页面，3D 舞台隐藏并暂停渲染。
- 横轴是**六个固定的年代列**，不按真实年份比例排：胶片（1990 前）/ 1990s CCD 数码 / 2000s CMOS / 2010s 背照与堆栈 / 2015+ 手机计算摄影 / 2020s 全局快门与 AI。每个节点用 `era` 字段决定放在哪一列，列内按 `year` 排序。年代之间有重叠是正常的，`era` 表示这个节点"属于哪个时代的故事"。*（实现者的决定）*
- 五条泳道：**镜头 · 传感器 · 图像处理 · 存储与传输 · 产品形态**。"产品形态"专门讲需求怎么改写行业，例如数码取代胶片与柯达衰落、手机吃掉卡片机、视频需求推动堆栈与全局快门、车载推动单帧 HDR。
- 卡片显示标题、年份和四格摘要；点开是一个详情抽屉，里面有一段故事、一张 2D 配图或小动画，以及"去看原理"按钮（可以有多个，每个对应一步）。
- 能横向拖动或滚动；`#/timeline/<id>` 直接定位并打开某张卡。

### 演进节点数据

新文件（例如 `js/evolution.js`）里放一个常量数组，每个节点：

```text
id, year（数字或范围文字）, era, lane,
title,
solved,       解决了旧技术什么问题
newProblem,   带来了什么新问题
driver,       什么需求推动
industry,     行业怎么变
story,        详情抽屉里的一段话
steps: [步骤编号…],   "去看原理"跳转目标；也决定演进卡挂在哪些步骤上
draw?: 2D 配图的绘制函数，或内联 SVG
```

覆盖要求：20–25 个节点，五条泳道每条至少 3 个，现有 31 步里讲到具体技术的步骤都至少挂 1 张演进卡。年份和关键事实要上网核对；无法确认的写成"约""前后"。

### 步骤数据

`steps.js` 每一步在现有 `t / g / cam / look / pn / h` 等字段之外，新增：

```text
ch      所属章 0–6
lead    入门层 HTML（带 <k data-hl> 关键词）
adv     进阶层 HTML（大体就是现在的 h）
hard?   硬核层 HTML（从现在的 h 里拆出公式、表格、厂商细节，没有就省略）
```

演进卡不写在步骤里，由演进节点的 `steps` 反查。

### 路由

- `#/step/<n>`：第 n 步（0–31）。
- `#/timeline`、`#/timeline/<id>`。
- 首次进入、没有 hash 时默认第 0 步。刷新后停在原来的位置。浏览器的前进后退要能用。
- *（实现者的决定）* 同一章内一步步切换时**替换**当前的历史记录，不新增；换章、进出时间轴、从演进卡或"去看原理"跳转时**新增**一条。这样用方向键翻完 32 步，历史记录里也不会堆 32 条。

### 视觉

- 讲解栏：米白纸感背景，标题用衬线体（宋体 / Georgia 系），正文用无衬线体，强调色砖红（约 `#c8502d`）。颜色全部定义成 `:root` 变量。
- 3D 舞台：保持深色背景。HTML 标注气泡（`.lb`）重新设计，在深色舞台上要清楚，风格和讲解栏一致。
- 讲解栏里所有 canvas 小图（取景器以外的透光曲线、信噪比曲线、ADC、快门、相位对焦、防抖轨迹、摩尔纹、ISP 九格等）的配色都改成适合浅色底的版本，统一从一个调色板对象取色。
- 第 25–31 步的新场景配色，和前 24 步统一到同一套强调色和材质风格。
- 入门层、进阶、硬核、演进卡要有清楚的视觉层级，一眼分得开。

### 手机（窄于约 768px）

3D 在上，约占屏幕高度 45%；讲解栏在下。章节导航和本章步骤横向滑动。时间轴泳道纵向排列，卡片在每条泳道里横向滑动。触控交互（旋转、缩放）保持现状。

### 完成标准

- 32 步（0–31）都能导航到；每步有入门层和进阶层，该有硬核的有硬核层。
- 20–25 个演进节点满足上面的覆盖要求；演进卡和"去看原理"双向跳转都能用。
- hash 深链接、刷新、前进后退都正常。
- 电脑和 375px 宽的手机上布局都正常，页面没有横向滚动。
- 把所有步骤和时间轴走一遍，控制台没有错误；现有所有控件功能不退化。
- 双击打开 `index.html` 仍然能用（联网加载 three.js）。
- README 更新：内容表、文件结构、准确性说明（新增演进线部分）。
